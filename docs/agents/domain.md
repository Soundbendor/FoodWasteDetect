# Domain docs

## Read before exploring

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root: shared domain vocabulary.
- `docs/adr/`: architectural decisions; read those relevant to the task.

If these files do not exist, proceed silently. Create them lazily through
the domain-modeling skill when terms or decisions are resolved.

Continue following the scoped guides and task references in `AGENTS.md`.
A shared glossary does not merge the separate pipeline contracts.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and test names.
If a needed concept is absent, reconsider whether it matches the project
or note the gap for domain-modeling.

## Decision conflicts

Explicitly identify proposals that contradict an existing ADR, cite the
decision, and explain why it should be reconsidered.
